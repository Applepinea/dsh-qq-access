# dsh-qq-access · 0.4.0

为 **DeepSeek Harness** 接入个人 QQ，支持私聊与群聊 AI 回复、可视化人设配置、NapCat 托管，以及 QQ 空间读取和留言。

**0.4.0** 加入批量回复、分条发送、轮询补漏、群聊 `@`、引用内容读取和本账号消息撤回，让 QQ 中的对话更连贯，也更接近日常聊天的节奏。

## 功能

| 功能 | 说明 |
| --- | --- |
| 私聊与群聊 | 自动回复，支持从 Harness 主动发送文本 |
| 批量回复 | 按周期合并同一会话中的待回复消息，默认每 60 秒处理一轮 |
| 分条发送 | 按换行、中英文逗号拆分最终回复，按文本长度控制发送节奏 |
| 消息补漏 | 轮询最近联系人与聊天历史，与推送消息去重归档 |
| 待回复恢复 | 从近期归档尝试恢复重载前尚未回复的会话 |
| 群聊互动 | 自动 `@` 触发回复的人，支持主动 `@` 成员和读取群成员资料 |
| 群内身份 | 向模型提供当前账号昵称及在该群的群名片 |
| 引用上下文 | 尝试读取被引用消息的内容，接口不可用时保留占位信息 |
| 消息撤回 | 撤回本账号在当前会话中发出并已归档的消息，限 2 分钟内 |
| 管理面板 | 左侧栏与设置页均有「QQ 接入」，可编辑人设、回复模式与范围 |
| NapCat 托管 | Windows x64 自动下载、校验、配置与管理运行进程 |
| QQ 空间 | 读取首页、说说、留言板的可见文字，发表留言板纯文本留言 |

插件通过 **NapCat / OneBot v11** 收发消息，通过 **Playwright** 访问 QQ 空间。当前以文字交互为主，媒体消息通常显示为类型占位文字。

## 环境要求

| 项目 | 要求 |
| --- | --- |
| DeepSeek Harness | 面向 **0.2.1-rc.3 Desktop**；包声明最低版本为 `0.2.1-rc.3` |
| 模型 | 在 Harness 中配置可用的提供商与默认模型 |
| Node.js | 独立执行初始化、登录与诊断命令时需要 **22.14.0 或更高版本** |
| NapCat 托管 | **Windows x64** |
| QQ 空间浏览器 | Windows 默认使用已安装的 **Microsoft Edge** |

未在插件配置中指定模型时，创建 QQ 会话会读取 Harness 的默认模型选择。需要固定模型时，同时填写配置中的 `model.provider` 与 `model.model`，使用宿主实际的 ID。

Linux、macOS 和 Windows ARM 使用 `external` 模式，自行准备可用的 NapCat / OneBot 服务与浏览器环境。

## 快速开始：Windows 桌面版

### 1. 初始化配置

下载 `dsh-qq-access-0.4.0.tgz`，在文件所在目录打开系统 PowerShell，执行：

```powershell
New-Item -ItemType Directory -Force .\qq-access-setup | Out-Null
tar -xf .\dsh-qq-access-0.4.0.tgz -C .\qq-access-setup
Set-Location .\qq-access-setup\package

npm.cmd install --omit=dev
node .\cli.mjs setup
```

解包是为了运行初始化工具；安装到 Harness 时仍使用下载的原始 `.tgz` 文件。发布包没有附带 lockfile，因此这里使用 `npm install`。

按提示输入登录 QQ 号，以及可选的管理员 QQ 号。管理员应使用**另一个账号**；留空时在电脑上的 Harness 中管理。

默认配置路径：

```text
%USERPROFILE%\.dsh-qq-access\config.json
```

Windows x64 的 `setup` 会生成连接密钥、启用托管模式并下载 NapCat 固定运行包，首次约 **118.3 MiB**。已有配置时不会覆盖，直接沿用或编辑原配置即可。

### 2. 安装插件

在 Harness 桌面版的**插件管理 → 添加插件**中，使用 `.tgz` 的完整路径安装并启用，然后重启 Harness。

如需命令行管理桌面插件，使用桌面版自带的 `dsh.cmd`。先启动一次桌面版完成初始化，再完全退出应用，替换下方路径后执行：

```powershell
& "你的DSH安装目录\resources\runtime\cli\bin\dsh.cmd" plugin --profile desktop add "C:\Plugins\dsh-qq-access-0.4.0.tgz"
```

完成后重新打开桌面版。独立 Web 版使用 `web` profile，插件应安装到实际使用的 profile 中。

### 3. 扫码登录

插件加载后启动 NapCat，登录页就绪时自动打开浏览器。使用配置中的 QQ 号扫码。

未自动打开时，在「QQ 接入」面板点击「打开 NapCat 登录页」，或在解包目录执行：

```powershell
node .\cli.mjs napcat-login
```

该命令会打开已有实例的登录页；没有运行实例时，会启动临时登录进程，扫码完成后关闭，再由 Harness 正式托管。默认扫码等待时间为 10 分钟。

### 4. 验证第一条回复

先在 Harness 中确认默认模型能够正常对话，再用另一个 QQ 账号发送私聊，或在群里 `@` 登录账号。

**默认按 60 秒周期批量处理，不会收到每条消息后立刻回复。** 等待下一轮处理与模型生成后，点击面板「刷新」查看状态；希望缩短等待时，可调整批量窗口，最小 15 秒。

## 可视化管理

左侧栏 **QQ 接入** 与设置页的同名入口使用同一套面板，支持：

- 查看昵称、QQ 号、在线状态及 NapCat 版本与运行状态，手动刷新。
- 开关私聊自动回复，选择群聊 `off` / `mention` / `all` 模式。
- 设置批量窗口，开关轮询补漏。
- 设置私聊接收范围、私聊白名单、群消息接收模式及管理员 QQ。
- 编辑人格设定和本地归档保留天数。
- 切换 NapCat 模式、修改 WebUI 端口、打开登录页。

点击 **保存设置** 写入配置；「放弃修改」会重新读取已保存的值。

| 设置 | 生效方式 |
| --- | --- |
| 自动回复与接收范围 | 保存后，后续接收的消息使用新配置 |
| 批量窗口与轮询开关 | 保存后重建定时器，无需重载 |
| 归档保留天数 | 保存后更新，超期记录由定期任务清理 |
| 人格设定 | 新建 QQ Agent 会话使用新设定；已有会话建议重载后统一更新 |
| 管理员权限 | 修改后建议重载，使已有会话的工具配置同步更新 |
| NapCat 模式与 WebUI 端口 | 保存后需要重载插件 |
| 模型、空间浏览器及其他高级项 | 编辑配置文件后重载插件 |

群聊白名单的群号目前通过 `access.groupIds` 填写，面板提供接收模式选择。选择「仅白名单群」前，应先配置群号。

## 回复节奏与消息恢复

### 批量窗口和轮询

默认每 **60 秒**运行一轮，先向 NapCat 查询近期消息，再处理待回复缓冲。同一会话以最新一条待回复消息触发一次模型回合，较早消息通过近期上下文提供给模型；上下文条数受 `reply.contextMessages` 限制。

| 配置 | 默认值 | 范围 / 用途 |
| --- | --- | --- |
| `poll.enabled` | `true` | 启用轮询与批量处理定时器 |
| `poll.intervalMs` | `60000` | 15000–3600000 毫秒；面板以秒填写 |
| `poll.count` | `10` | 每个会话查询 1–50 条近期历史 |

**当前实现中，轮询与批量回复共用定时器。** 关闭「轮询补漏」或设置 `poll.enabled: false` 后，推送仍可归档，但待回复缓冲不会被定时处理。需要正常自动回复时，请保持该开关开启。

轮询优先覆盖已归档会话与 NapCat 最近联系人。推送与轮询获得的重复消息会去重；长时间离线、接口不可用或会话已滑出最近列表时，不能保证补回所有消息。

### 分条发送

自动回复的最终文本会按**换行、中文逗号、英文逗号**拆成多条 QQ 消息，数字中的逗号（如 `1,000`）与完整 CQ 码会受到保护。

- 每轮自动分条最多发送 **8 段**，超出部分不会发送。
- 每段超过 `reply.maxChars` 时截断，默认上限 **2000 字符**。
- 分段间隔按文本长度计算，计算值约 **1–10 秒**，实际发送还受 `rate.peerGapMs`、全局间隔和每分钟限额约束。

可以在人设中要求模型「用换行区分要独立发送的短句」，让分条边界更容易控制。通过发送工具直接发出的消息，不再由自动收尾流程重复补发。

### 重载后的待回复恢复

处理缓冲前，插件会检查近期归档，尝试恢复「最新入站消息晚于最新出站消息」且符合自动回复模式的会话。默认回溯 **10 分钟**，不能替代完整历史同步，也不保证恢复所有离线期间的消息。

## 群聊互动与权限

### @ 成员

群聊自动回复的第一段默认 `@` 触发该轮回复的发送者，可在配置文件中设置 `reply.mentionSender: false` 关闭。

从本机 Harness 或管理员私聊主动发送时，`qq_send_message` 支持 `mentions` 参数：

- QQ 号字符串数组，例如 `["234567890"]`。
- `["all"]` 表示 `@` 全体成员，是否成功取决于群权限与接口返回。
- `mentions` 最多 10 项，仅群聊可用。

群聊回复正文中的 `[CQ:at,qq=234567890]` 也会转换为真实 `@` 消息段。插件会向群聊 Agent 说明这一能力。

### 昵称、群名片与引用

插件向模型提供登录账号昵称，以及当前群中的群名片。查询其他成员资料时，可由本机 Harness 或管理员私聊调用 `qq_group_member_info`；不传 `user_id` 则查询本账号。

收到带引用的消息时，插件尝试通过 `get_msg` 读取部分被引用文字并加入上下文。接口失败或超时时，降级为引用占位信息，不保证还原所有引用内容。

### 撤回消息

`qq_recall_message` 只撤回**本账号在目标会话中发出并已归档的消息**，且限制在 **2 分钟内**：

- 提供 `message_id`：核对消息归属、会话与发送时间。
- 省略 `message_id`：查找本会话最近一条符合条件的本账号消息。
- 普通私聊和群聊会话都可请求撤回，但只能操作当前会话中的本账号消息。

可以直接说「撤回你刚才那条消息」。撤回请求也会受到批量等待影响，窗口过长时可能已超过 2 分钟；需要及时操作时，可从本机 Harness 发起。

| 发起位置 | 工具能力 |
| --- | --- |
| 本机 Harness | 可调用插件管理工具；聊天目标仍受配置约束 |
| 已配置的管理员私聊 | 可查询联系人、主动发送、查询群资料和操作空间等 |
| 普通私聊 | 本会话状态、历史，以及本账号在该会话中的近期消息撤回 |
| 群聊 | 本群状态、历史，以及本账号在本群中的近期消息撤回；群内声明不授予管理员私聊权限 |

`ownerHarnessTools` 默认为 `false`。开启后，管理员私聊可进一步使用宿主其他工具。

## 人设与访问范围

在人格设定中填写称呼、性格、语气和回复习惯，例如：

> 你叫小溪，语气自然，偶尔有一点傲娇但不刻薄。用简短中文聊天，想分开发送的短句用换行表示，日常聊天少用句号。认真听对方表达，诚实说明自己是 AI，尊重其他会话的隐私。

更细的配置参考 [配置示例](examples/config.example.json)。下例为合并到现有 `config.json` 的片段，QQ 号与群号均使用字符串：

```json
{
  "ownerIds": ["234567890"],
  "access": {
    "privateMode": "allowlist",
    "privateIds": ["234567890", "345678901"],
    "groupMode": "allowlist",
    "groupIds": ["456789012"],
    "blockedUsers": [],
    "blockedGroups": []
  },
  "reply": {
    "private": true,
    "group": "mention",
    "mentionSender": true,
    "maxChars": 2000,
    "contextMessages": 20
  },
  "poll": {
    "enabled": true,
    "intervalMs": 60000,
    "count": 10
  },
  "retentionDays": 30
}
```

私聊设为白名单时，需将管理员账号也加入 `privateIds`。关闭自动回复会继续归档接收范围内的消息；将接收范围设为 `disabled`，则忽略对应的新入站消息。

## QQ 空间：独立登录

空间登录与 NapCat 分开。首次使用时，在解包目录执行：

```powershell
node .\cli.mjs qzone-login
```

在弹出的独立 Edge 窗口中登录与 `selfId` 相同的 QQ，确认页面登录完成后回终端按回车。关闭登录窗口后再使用空间工具。

读取范围为 `home` 首页、`shuoshuo` 说说页和 `guestbook` 留言板的当前可见文字。写入范围为**留言板纯文本留言**，不包含说说评论、发说说或相册导出。登录状态失效时，重新执行 `qzone-login`。

### 操作回执与去重

发送、撤回和留言使用唯一的 `request_id`，相同操作重试时复用同一标识。

| 状态 | 含义 |
| --- | --- |
| `sent` | 已取得操作成功的回执或证据 |
| `failed` | 操作被明确拒绝，或已知未成功 |
| `pending` | 请求已登记，尚未完成确认 |
| `uncertain` | 已提交或可能已提交，结果不能确认 |

空间留言可能已经发表，但因页面刷新或确认逻辑偏保守返回 `uncertain`。此时先到真实留言板核对，避免更换新 `request_id` 再发一次。复用原标识会读取已有记录。

## NapCat 模式与离线准备

**`managed` 托管模式**：Windows x64 由插件下载并校验固定的 `v4.18.41 / NapCat.Shell.Windows.Node.zip`，生成 API、事件上报和 WebUI 配置，随插件启动并管理自有进程。意外退出后默认最多重启 2 次。

旧配置切换到托管，使用以下命令准备密钥、备份配置并安装运行包：

```powershell
node .\cli.mjs napcat-enable
```

仅在面板选择托管模式，不会替代首次启用时所需的配置准备。运行包下载失败可执行 `napcat-install` 重试，或从 [固定版本 Release](https://github.com/NapNeko/NapCatQQ/releases/tag/v4.18.41) 下载对应文件后离线安装：

```powershell
node .\cli.mjs napcat-install --archive "C:\Downloads\NapCat.Shell.Windows.Node.zip"
```

**`external` 外部模式**：自行启动 NapCat / OneBot 实例，插件连接其本机 API。网络配置可参考 [示例](examples/napcat-network.example.json)。

| 连接 | 默认地址 | 对应配置 |
| --- | --- | --- |
| OneBot HTTP API | `http://127.0.0.1:3000` | `onebot.token` |
| HTTP 事件上报 | `http://127.0.0.1:5701/onebot` | `events.secret` |
| 托管 WebUI | `http://127.0.0.1:6099/webui` | `napcat.webuiToken` |

NapCat HTTP 上报的 token 应与 `events.secret` 一致，用于验证 `X-Signature`。API、上报接收和 WebUI 端口不能重复；插件当前要求 OneBot API 位于本机。

## 排查问题

### 只读诊断

```powershell
node .\cli.mjs doctor
```

检查配置、运行包、登录账号与基础接口，不发送消息或发表留言。尚未扫码或 Harness 未启动时，连接检查失败不一定代表安装失败。

自定义配置路径示例：

```powershell
node .\cli.mjs doctor --config "D:\QQAssistant\config.json"
```

宿主也可通过插件的 `configPath` 或环境变量 `DSH_QQ_CONFIG` 指定配置。独立命令与宿主应指向同一份文件。

| 现象 | 检查方式 |
| --- | --- |
| 能收消息但没有回复 | 等待批量周期；检查默认模型、自动回复模式、接收范围及 `poll.enabled` |
| 群里不回复 | 默认只在被 `@` 时入队；核对群接收范围与白名单 |
| 回复被拆得太碎 | 减少模型输出中的逗号，用换行明确独立消息；一轮最多 8 段 |
| 撤回失败 | 核对归档、消息归属与 2 分钟窗口；批量等待也会消耗撤回时间 |
| 人设没有更新 | 重载插件，让已建立的 QQ Agent 会话重新创建 |
| 找不到面板 | 重启 Harness，在左侧栏或设置页查找「QQ 接入」；未配置时先执行 `setup` |
| NapCat 端口不可用 | 检查本机占用及保留端口，选择可用端口后重载插件 |
| 目录被使用 | 插件会检查遗留锁对应的进程；仍有实例存活时先退出重复实例 |

默认诊断日志为 `%USERPROFILE%\.dsh-qq-access\debug.log`；NapCat 控制台日志位于配置目录的 `data\napcat\logs\console.log`。日志与管理面板可能包含本机路径或登录信息，分享前应处理敏感内容。

## 升级与源码使用

升级时在原 profile 安装新的 `.tgz`，保留原配置，然后重启 Harness。不要只修改 `node_modules/dsh-qq-access`：依赖重装时，这些修改可能被原安装包覆盖。

在包含 `package.json`、`cli.mjs` 与 `lib/` 的源码目录中，可执行：

```powershell
npm.cmd install
node .\cli.mjs setup
npm.cmd pack
```

发布包中的 `lib/client.js` 已是可加载的客户端文件。打包文件名由 `package.json` 的版本决定，发布时保持版本号、包名和 Release 标签一致。

## 数据与功能边界

- 本地归档默认保留 **30 天**，从插件开始接收消息后累积；不保证补全安装前的全部历史。
- 轮询与待回复恢复只覆盖有限的近期记录，不能替代 QQ 完整历史同步。
- 空间读取仅输出当前页面可见文字；权限、验证码、页面结构与登录状态会影响操作。
- 当前不提供图片、语音、视频理解和完整空间备份。
- 用于回复或主动查询的文本会进入 Harness 选用的模型服务。
- 归档清理只影响本插件本地记录，不会删除 QQ、Harness 会话或模型服务侧的数据。
- 管理面板面向本机可信环境，会显示带 token 的 NapCat 登录链接。
